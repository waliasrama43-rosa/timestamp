# Mobile fix and overlay UI corrections for TrustMark

Six changes bundled in a single feature targeting the TrustMark Google Apps Script web app's `index.html`. The critical fix replaces escaped script closing tags (`<\/script>`) with standard `</script>`, which was preventing the app from loading on mobile since the browser couldn't parse the CDN script includes. The remaining five changes rework the photo overlay renderer: white background instead of dark, darker text, vertical VRF code on the right edge, longer VRF codes, always-visible logo, and tighter line spacing.

**Watch for:** The free-tier watermark still renders in white (`#FFFFFF`) on what is now a white overlay background — it will be invisible (confirmed). The VRF code's vertical positioning is anchored at the overlay's vertical midpoint, but the text length nearly doubled (from ~10 to ~16 chars with prefix); whether it clips outside the overlay bounds on narrow images is worth checking (likely).

## High-level view

The script tag fix solves the mobile-blocking bug. Google Apps Script's `HtmlService` serves the HTML directly to the browser; the escaped `<\/script>` pattern is a JavaScript-string idiom that doesn't belong in raw HTML and caused parse failures on mobile WebKit.

The overlay redesign inverts the visual scheme from light-on-dark to dark-on-light. The golden header line stays gold, while all subsequent text becomes `#333333` on a white-75%-opacity background. The VRF badge changes from a horizontal inline element to a vertically-rotated label running along the right edge. However, the free-tier watermark was not updated to match the new background and is now white-on-white.

The tier restriction on logo display has been removed entirely, so free-tier users now see their uploaded logo. Combined with the still-present (but invisible) watermark, the free-tier experience is in an inconsistent state.

## Watermark color inversion missed

The free-tier watermark block at the end of `renderOverlay` still sets `ctx.fillStyle = '#FFFFFF'` (line ~1200). With the overlay background now `rgba(255,255,255,0.75)`, white text at 30% opacity on a white surface is effectively invisible. The watermark color should have been updated to a dark shade (e.g., `#333333` or `#000000`) to match the background inversion applied to all other text in the overlay.

```javascript
// Free tier watermark — still white on white
ctx.globalAlpha = 0.3;
ctx.fillStyle = '#FFFFFF';  // ← should be dark now
```

## Vertical VRF code clipping risk

The VRF text is drawn at `vrfX = w - padding * 0.8` (right edge) and `vrfY = overlayY + overlayHeight * 0.5` (vertical center of overlay), then rotated −90°. With `textAlign = 'center'`, the rendered text extends equally above and below that midpoint. The VRF code is now 16 characters (`VRF-` + 12 alphanumeric), rendered in monospace at `fontSize * 0.7`. For a 1000px-wide image: `vrfFontSize ≈ 15px`, each glyph ~9px, total rendered width ~144px, overlay height ~187px — it fits with ~20px margin per side. But the overlay height floor is `Math.max(..., 120)`, and on narrow images where the formula yields that floor, 144px of text inside 120px of overlay will clip top and bottom.

## Logo and tier state inconsistency

The condition `state.logoImage && state.tier !== 'free'` is now just `state.logoImage`, meaning free-tier users see their uploaded logo on the overlay. The free-tier watermark still renders separately, so free users would now see both their logo and a watermark — except the watermark is currently invisible. The task description says "logo now always shows when uploaded" which suggests the logo change is deliberate, but the watermark's continued presence (if fixed) would create an odd UX of showing both branding and a "free" mark simultaneously.
